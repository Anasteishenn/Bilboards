# Bilboards
# AdBoard C++ — Информационная система управления наружной рекламой

Консольная информационная система (ИС) для автоматизации процессов бронирования и управления рекламными поверхностями (билбордами, цифровыми экранами).

Проект разработан в рамках расчетной работы по дисциплине **«Проектирование ПО в ИС»**. Фокус разработки направлен на строгую инженерную архитектуру: разделение обязанностей по принципам SOLID, использование классических паттернов проектирования GoF (Repository, Strategy, Dependency Injection), безопасное хранение реляционных данных в SQLite и кроссплатформенную модульную сборку через CMake.

---

## Ключевой функционал по ролям пользователей

Система предоставляет терминальный интерфейс (CLI) с ролевой моделью доступа:

* **Клиент (Арендатор):**
  * Регистрация и аутентификация в системе (с валидацией и хэшированием пароля).
  * Просмотр каталога рекламных щитов в виде форматированных таблиц.
  * Фильтрация конструкций по району, формату (Static, Digital, Prismatron) и суточной ставке.
  * Формирование заявки на аренду с выбором временного интервала (`start_date` — `end_date`).
  * Автоматический расчет стоимости с применением скидок за длительность аренды.
  * Отслеживание статусов своих заказов (`Pending`, `Approved`, `Rejected`).

* **Менеджер (Оператор агентства):**
  * Просмотр входящей очереди бронирований.
  * Модерация заявок: подтверждение (`Approved`) или отклонение (`Rejected`).
  * Автоматическая блокировка дат для других клиентов при подтверждении заказа.
  * Аналитический отчет по занятости инвентаря и финансовым показателям.

* **Администратор (Управление инвентарем):**
  * Добавление новых поверхностей в базу данных (адрес, район, формат, базовая ставка).
  * Редактирование параметров и списание (деактивация) конструкций.

## Архитектура системы (3-Tier Architecture)

Проект построен по классической трехслойной модели с инверсией зависимостей (DIP):

```text
┌────────────────────────────────────────────────────────┐
│               СЛОЙ 3: APPLICATION / CLI                │
│       (ConsoleApp, ClientView, ManagerView, main.cpp)  │
└───────────────────────────┬────────────────────────────┘
                            │ вызывает методы сервисов
┌───────────────────────────▼────────────────────────────┐
│               СЛОЙ 1: CORE / DOMAIN                    │
│  Модели: User, Billboard, BookingOrder, DateRange      │
│  Сервисы: AuthService, BillboardService, BookingService│
│  Контракты: IUserRepository, IBillboardRepository      │
│             IOrderRepository, IPricingStrategy         │
└───────────────────────────┬────────────────────────────┘
                            │ вызывает абстрактные интерфейсы
┌───────────────────────────▼────────────────────────────┐
│          СЛОЙ 2: INFRASTRUCTURE / STORAGE              │
│      (DatabaseManager, Sqlite...Repository, SQLite3)   │
└────────────────────────────────────────────────────────┘
```
## 3. Зоны ответственности в команде

### Разработчик №1: Core / Domain Engineer (Бизнес-логика и модели)
* **Зона ответственности:** Модуль `Core / Domain + Service`. «Мозг» системы: создает независимое ядро — классы сущностей, правила бронирования, математику цен и абстрактные интерфейсы. Этот модуль не знает, как данные сохраняются на диск и как они выводятся на экран.
* **Закрепленные компоненты:**
  * Доменные модели: `User`, `Billboard`, `BookingOrder`, `DateRange`.
  * Сервисы: `AuthService` (проверка логина/пароля, хеширование), `BookingService` (алгоритм проверки коллизий дат), `BillboardService` (выборки и фильтрация каталога).
  * Контракты (интерфейсы): `IUserRepository`, `IBillboardRepository`, `IOrderRepository`, `IPricingStrategy`.
* **Ключевые задачи:**
  * Реализовать структуры и классы: `User.hpp`, `Billboard.hpp` / `.cpp`, `BookingOrder.hpp` / `.cpp`, `DateRange.hpp` / `.cpp`.
  * Написать чистые абстрактные интерфейсы репозиториев (`IUserRepository.hpp`, `IBillboardRepository.hpp`, `IOrderRepository.hpp`), по которым с базой будет работать остальной код.
  * Реализовать логику `BookingService`: алгоритм пересечения дат (щит нельзя занять на уже занятый интервал) и расчет скидок через паттерн Strategy.
  * Реализовать логику `AuthService`: регистрация, детерминированное хеширование паролей, валидация сессии.
* **Материалы для отчета:** Диаграмма классов (Class Diagram), обоснование паттерна Strategy (для расчета цен), математическое описание алгоритма проверки пересечения интервалов времени.

### Разработчик №2: Infrastructure & Data Engineer (Хранилище и Сборка)
* **Зона ответственности:** Модуль `Infrastructure / Storage + Build System`. «Фундамент» системы: оживляет интерфейсы первого разработчика — развертывает движок SQLite, пишет SQL-запросы, настраивает компиляцию проекта через CMake и автоматическую инициализацию базы.
* **Закрепленные компоненты:**
  * Скрипт БД: `data/schema.sql` (таблицы, внешние ключи, типы полей, начальные данные).
  * Движок: подключение SQLite (`third_party/sqlite3.c`, `third_party/sqlite3.h`).
  * Реализация репозиториев: `DatabaseManager`, `SqliteUserRepository`, `SqliteBillboardRepository`, `SqliteOrderRepository`.
  * Сборка: `CMakeLists.txt` и настройка `.gitignore`.
* **Ключевые задачи:**
  * Написать `CMakeLists.txt` и `.gitignore`, чтобы проект компилировался одной командой у всех участников.
  * Подключить движок SQLite (amalgamation в `third_party/`).
  * Спроектировать схему таблиц с внешними ключами и ограничениями целостности (`data/schema.sql`).
  * Написать класс `DatabaseManager`, который при старте создает `adboard.db` и накатывает таблицы из SQL-скрипта.
  * Реализовать репозитории: превращать строки из SQL-выборок в объекты C++ и сохранять новые записи.
* **Материалы для отчета:** Схема базы данных (ER-диаграмма связей 1:N), описание структуры таблиц и DDL-скриптов, реализация паттерна Repository и механизма транзакций/целостности данных.

### Разработчик №3: Application & CLI Engineer (Интерфейс и Интеграция)
* **Что делает:** Модуль `Application / CLI + Git/Документация`. «Лицо» системы: собирает работающее приложение, реализует удобный текстовый интерфейс терминала, связывает сервисы в `main.cpp`, обрабатывает ошибки ввода пользователя и оформляет проект на GitHub.
* **Закрепленные компоненты:**
  * Главное меню и маршрутизация: `ConsoleApp`.
  * Представления: `ClientView` (каталог, фильтры, аренда), `ManagerView` (список заявок, одобрение/отклонение, отчеты).
  * Точка входа: `src/main.cpp` (создание зависимостей и запуск).
  * Репозиторий: `README.md`, ведение веток Git, оформление графических диаграмм.
* **Ключевые задачи:**
  * Оформить стартовый экран, цикл авторизации и переключение меню по ролям (`ConsoleApp`).
  * Реализовать рабочие экраны `ClientView` (ввод дат, отрисовка каталога в виде форматированных таблиц) и `ManagerView` (список заявок, модерация, аналитика).
  * Написать точку входа `src/main.cpp`: создать подключение к БД, передать репозитории в сервисы, а сервисы — в меню (Composition Root).
  * Защитить ввод пользователя от падений (валидация потока `std::cin`, сброс флагов ошибок и очистка буфера).
  * Вести репозиторий: написать презентабельный `README.md` с инструкцией по запуску.
* **Материалы для отчета:** Диаграмма прецедентов (Use Case Diagram), диаграмма последовательности (Sequence Diagram), руководство пользователя со сценариями и скриншотами консоли.
